## Overview

PatternSnap is a full-stack sewing-pattern editor with two modes: a Phase 1 hand-drafting canvas (draw lines, curves, grain lines, and annotate pieces), and a Phase 2 AI Assist flow that analyses a garment photograph with Claude Vision and generates a ready-to-edit `.psnap` pattern file. The React/TypeScript frontend communicates with a FastAPI/Python backend over a simple REST API. All internal geometry is stored in centimetres; units are converted only for display.

## Layers & Modules

### Frontend

#### App Shell · `frontend/src/App.tsx`
**Role:** Root component that composes the full editor layout (header, toolbar, canvas, right sidebar, status bar) and owns the file save/open/PDF-export buttons.
**Inputs:** None at mount; re-renders driven by EditorContext state changes.
**Outputs:** Rendered UI; triggers `LOAD_STATE` dispatch on file open; calls `/api/export/pdf` for PDF export; calls `downloadSVG` for SVG export.
**Depends on:** EditorContext, Canvas, Toolbar, PropertiesPanel, MeasurementPanel, AIAssistModal, svgExport.

---

#### Editor Context · `frontend/src/context/EditorContext.tsx`
**Role:** Single-source-of-truth state store for the editor, implemented as a `useReducer`; manages elements, pattern pieces, measurements, selection, active tool, zoom/pan, and a 50-level undo/redo stack.
**Inputs:** Action objects dispatched by any consumer component (see `Action` union type).
**Outputs:** `{ state: EditorState, dispatch }` provided via React context.
**Depends on:** types/index.ts, utils/pieceTransforms.

---

#### Pattern Context · `frontend/src/context/PatternContext.tsx`
**Role:** Lightweight state machine for the AI wizard flow (wizard step, raw image files, detected/confirmed features, generated SVG); kept separate from EditorContext so the wizard can be torn down without resetting the canvas.
**Inputs:** Wizard-step action objects.
**Outputs:** `{ state: PatternState, dispatch }` via React context.
**Depends on:** types/index.ts.

---

#### Canvas · `frontend/src/components/Canvas.tsx`
**Role:** SVG-based interactive drawing surface; handles all tool modes (select, line, curve, grain-line, notch, eraser), drag/resize/rotate, seam allowance visualisation, piece hit-testing, and keyboard shortcuts.
**Inputs:** Reads EditorContext state; receives DOM pointer events.
**Outputs:** Dispatches `ADD_ELEMENT`, `UPDATE_ELEMENT`, `DELETE_ELEMENTS`, `BATCH_UPDATE_ELEMENTS`, `LIVE_UPDATE_ELEMENTS`, `ADD_PIECE`, `SELECT_PIECE`, `PUSH_UNDO` etc. to EditorContext.
**Depends on:** EditorContext, snap-engine, piece-transforms, types.

---

#### Toolbar · `frontend/src/components/Toolbar.tsx`
**Role:** Vertical strip of tool buttons; dispatches `SET_ACTIVE_TOOL`, `TOGGLE_GRID`, `TOGGLE_SNAP`, `TOGGLE_SEAM_ALLOWANCE`, `SET_UNIT_SYSTEM` to EditorContext.
**Inputs:** Reads `state.activeTool`, `state.showGrid`, `state.snapEnabled` from EditorContext.
**Outputs:** Dispatches tool selection and toggle actions.
**Depends on:** EditorContext.

#### AI Assist Modal · `frontend/src/components/AIAssistModal.tsx`
**Role:** Three-step modal wizard (upload → review → generating) that calls the backend to analyse a garment photo, lets the user correct detected features, then triggers pattern generation and loads the result into the canvas.
**Inputs:** `onClose` callback; reads EditorContext measurements to seed defaults; receives photo `File` objects from the user.
**Outputs:** POSTs `multipart/form-data` to `/api/analyze`; POSTs JSON to `/api/generate`; dispatches `LOAD_STATE` to EditorContext on success.

### Backend

#### FastAPI App · `backend/app/main.py`
**Role:** Creates the FastAPI application, loads `.env`, registers CORS middleware (origin list from `CORS_ORIGINS` env var), mounts all API routers under `/api`, creates database tables on startup via `lifespan`, and exposes `/api/health` and `/api/garment-types`.
**Inputs:** Environment variables; HTTP requests.
**Outputs:** ASGI app; database tables created on first start.
**Depends on:** All API routers, database, features-model.

---

#### Analyze Router · `backend/app/api/analyze.py`
**Role:** Handles `POST /api/analyze` — validates the uploaded image files (type + size), delegates to the vision analyzer, and returns the structured `GarmentFeatures` response.
**Inputs:** `multipart/form-data`: `garment_type`, `front_image` (required), `back_image` (optional).
**Outputs:** `GarmentFeatures` JSON (200) or 400/422/502 error.
**Depends on:** vision-analyzer, features-model.

---

#### Generate Router · `backend/app/api/generate.py`
**Role:** Handles `POST /api/generate` — receives confirmed `GarmentFeatures` and `Measurements`, delegates to the pattern engine, and returns the `.psnap` JSON document.
**Inputs:** JSON body `{ features: GarmentFeatures, measurements: Measurements }`.
**Outputs:** `.psnap` JSON document (200) or 500 error.
**Depends on:** pattern-engine, features-model, measurements-model.

---

#### Export Router · `backend/app/api/export.py`
**Role:** Handles `POST /api/export/pdf` — accepts raw elements and pieces, passes them to the PDF tiler, and returns the PDF binary as an attachment.
**Inputs:** JSON body `{ elements, pieces, paper_size, single_page }`.
**Outputs:** `application/pdf` binary response.
**Depends on:** pdf-tiler.

---

#### Patterns Router · `backend/app/api/patterns.py`
**Role:** Full CRUD REST resource for saved patterns (`/api/patterns`): create, list (with garment-type filter + pagination), get by ID, update, delete. Stores geometry as a JSON blob in SQLite.
**Inputs:** HTTP CRUD requests; SQLAlchemy DB session via dependency injection.
**Outputs:** `PatternResponse` / `PatternListItem` JSON.
**Depends on:** database, pattern-orm, pattern-schemas.

---

#### Templates Router · `backend/app/api/templates.py`
**Role:** Developer-facing endpoints for inspecting and deleting learned piece templates: `GET /api/templates`, `GET /api/templates/{id}`, `DELETE /api/templates/{id}`.
**Inputs:** HTTP requests.
**Outputs:** Template JSON / 404 errors.
**Depends on:** learned-pieces.

---

#### Vision Analyzer · `backend/app/vision/analyzer.py`
**Role:** Calls the Anthropic Claude Vision API with base64-encoded garment images, parses the structured JSON response into `GarmentFeatures`, infers missing pocket detail tokens from the free-text `notes` field, and retries on overload/rate-limit errors (schedule: 3 s, 8 s, 15 s).
**Inputs:** `garment_type: GarmentType`, `front_bytes: bytes`, `back_bytes: bytes | None`.
**Outputs:** `GarmentFeatures` Pydantic model.
**Depends on:** vision-prompts, features-model, Anthropic SDK (external).

---

#### Vision Prompts · `backend/app/vision/prompts.py`
**Role:** Builds per-garment-type system prompts dynamically from a vocabulary dictionary (`_GARMENT_VOCAB`); each prompt lists the exact allowed values for silhouette, length, closure, details, and (where applicable) sleeve length and neckline.
**Inputs:** `garment_type: GarmentType`.
**Outputs:** `system_prompt: str`, `user_prompt: str`.
**Depends on:** features-model.

---

#### Pattern Engine · `backend/app/patterns/engine.py`
**Role:** Top-level pattern generation orchestrator: dispatches to the garment-specific block builder, applies silhouette modifiers, serialises `PieceSpec` objects into `.psnap` JSON (lines, curves, grain lines, dart markings), appends the waistband piece, and calls the LLM fallback for any unsupported detail strings.
**Inputs:** `features: GarmentFeatures`, `measurements: Measurements`.
**Outputs:** `.psnap` dict `{ version, elements, pieces, measurements }`.
**Depends on:** skirts-builder, shirts-builder, trousers-builder, silhouette-modifiers, geometry, llm-fallback, features-model, measurements-model.

---

#### Skirts Builder · `backend/app/patterns/skirts.py`
**Role:** Generates parametric skirt pattern blocks for 12+ silhouettes (straight, pencil, a-line, circle, gathered, pleated, wrap, trumpet, mermaid, tulip, tiered); handles pockets, kick pleat, side slits, and ruffle tier as optional additional `PieceSpec` objects.
**Inputs:** `measurements: Measurements`, fit style, length category, closure type, pocket flags.
**Outputs:** `dict[str, PieceSpec]` (e.g. `{ "front": ..., "back": ..., "pocket_bag": ... }`).
**Depends on:** geometry, measurements-model.

---

#### Shirts Builder · `backend/app/patterns/shirts.py`
**Role:** Generates parametric shirt/blouse pattern blocks: front body, back body, sleeve (with optional cuff), collar (multiple styles), and button placket; adjusts chest ease by fit style.
**Inputs:** `measurements: Measurements`, chest ease, fit style, sleeve length, neckline, feature flags.
**Outputs:** `dict[str, PieceSpec]`.
**Depends on:** geometry, measurements-model.

---

#### Trousers Builder · `backend/app/patterns/trousers.py`
**Role:** Generates parametric trouser/pants pattern blocks: front and back leg panels (with crotch curve), fly shield, waistband, pockets (side, cargo, welt), and cuff band; parameterised by fit, rise, and length style.
**Inputs:** `measurements: Measurements`, fit style, rise style, length category, closure type, pocket/feature flags.
**Outputs:** `dict[str, PieceSpec]`.
**Depends on:** geometry, measurements-model.

---

#### Silhouette Modifiers · `backend/app/patterns/modifiers.py`
**Role:** Post-processes a base block `dict[str, PieceSpec]` to reshape the hem/outline for a specific silhouette (pencil = taper, a-line = flare +5 cm, circle = 2× width, wrap = flare + extend waist 15 cm).
**Inputs:** `base_pieces: dict[str, PieceSpec]`, `features: GarmentFeatures`, `measurements: Measurements`.
**Outputs:** Modified `dict[str, PieceSpec]`.
**Depends on:** geometry, features-model, measurements-model, skirts-builder (imports `PieceSpec`).

---

#### Geometry · `backend/app/patterns/geometry.py`
**Role:** Pure 2D geometry primitives used by all pattern builders: `Point` (with arithmetic operators, lerp, perp, dot), `CurveSegment` (cubic Bezier vertex), polygon offset (miter join), cubic/quadratic Bezier sampling and arc-length measurement.
**Inputs:** Coordinate arguments.
**Outputs:** `Point`, `CurveSegment`, sampled polylines, lengths.
**Depends on:** Nothing.

---

#### LLM Fallback · `backend/app/patterns/llm_fallback.py`
**Role:** Detects garment detail strings that the parametric engine cannot produce (not in `_PARAMETRIC_DETAILS`), checks the learned template store, and — if no template exists — calls Claude synchronously with a structured prompt to generate parametric piece formulas; saves each new template for future reuse.
**Inputs:** `unsupported_details: list[str]`, `features: GarmentFeatures`, `measurements: Measurements`.
**Outputs:** `list[PieceSpec]` (one or more extra pieces appended to the pattern).
**Depends on:** learned-pieces, features-model, measurements-model, Anthropic SDK (external).

---

#### Learned Pieces · `backend/app/patterns/learned_pieces.py`
**Role:** JSON-backed `TemplateStore` singleton that persists LLM-generated piece formulas to `patterns/templates/learned.json`; provides find-by-detail, add, remove, and record-use operations; evaluates formula strings safely (no `eval` injection — validated against an allowlist) to produce `PieceSpec` objects.
**Inputs:** `detail: str`, `garment_type: str`, `measurements: Measurements`.
**Outputs:** `PieceTemplate | None` (lookup); `PieceSpec` (after applying a template).
**Depends on:** geometry, measurements-model, learned-json file (infra).

---

#### Features Model · `backend/app/models/features.py`
**Role:** Pydantic definitions for `GarmentType` (11-value enum), `WaistbandFeature`, `ClosureFeature`, `DartFeature`, and the generic `GarmentFeatures` model that the vision layer returns and the pattern engine consumes; also exports legacy `SkirtFeatures`.
**Inputs:** Imported — no runtime behaviour.
**Outputs:** Validated Pydantic model instances.
**Depends on:** Nothing.

#### Measurements Model · `backend/app/models/measurements.py`

**Inputs:** Imported — no runtime behaviour.
**Outputs:** Validated `Measurements` instance.
**Depends on:** Nothing.

## Data Flows

### AI Pattern Generation Flow
**Trigger:** User clicks "AI Assist" button in the editor header, selects a garment type, uploads a front (and optional back) photo, then confirms detected features.

1. App Shell — renders AIAssistModal
2. AI Assist Modal (upload step) — POSTs `multipart/form-data` to `POST /api/analyze`
3. Analyze Router — validates images, calls `analyze_garment()`
4. Vision Analyzer — builds per-garment-type prompt via Vision Prompts
5. Vision Analyzer — calls Anthropic Claude API with base64 images (retries on overload)
6. Vision Analyzer — parses JSON → `GarmentFeatures`; infers pocket tokens from notes
7. Analyze Router — returns `GarmentFeatures` to AIAssistModal
8. AI Assist Modal (review step) — user edits features + enters measurements
9. AI Assist Modal — POSTs `{ features, measurements }` to `POST /api/generate`
10. Generate Router — calls `generate_pattern(features, measurements)`
11. Pattern Engine — dispatches to garment builder (Skirts / Shirts / Trousers Builder)
12. Garment Builder — produces `dict[str, PieceSpec]`; Geometry used for all calculations
13. Pattern Engine — calls Silhouette Modifiers to reshape hem/outline
14. Pattern Engine — serialises `PieceSpec` objects → `.psnap` JSON elements + pieces
15. Pattern Engine — calls LLM Fallback for any unsupported detail strings
16. LLM Fallback — checks Learned Pieces store; on miss calls Claude; saves new template
17. Pattern Engine — returns complete `.psnap` dict
18. Generate Router — returns `.psnap` JSON to AIAssistModal
19. AI Assist Modal — dispatches `LOAD_STATE` to EditorContext
20. Canvas — re-renders with all generated pattern pieces visible

---

### Manual Drawing Flow
**Trigger:** User selects a draw tool from the Toolbar.

1. Toolbar — dispatches `SET_ACTIVE_TOOL` to EditorContext
2. Canvas — reads `activeTool` from EditorContext; enters draw mode
3. Canvas — on pointer down: computes snapped position via Snap Engine
4. Canvas — on pointer up: dispatches `ADD_ELEMENT` (+ `PUSH_UNDO`) to EditorContext
5. EditorContext — stores new element; old state pushed to undo stack
6. Canvas — re-renders; seam allowance visualised automatically if enabled

---

### Save / Export Flow
**Trigger:** User clicks Save (.psnap), Export SVG, or Export PDF.

**Save (.psnap):**
1. App Shell (FileButtons) — serialises `{ version, elements, pieces, measurements }` to JSON
2. App Shell — creates `Blob` and triggers browser download as `pattern.psnap`

**Export SVG:**
1. App Shell — calls `downloadSVG(elements, pieces)` in svgExport module
2. SVG Export — builds SVG string with fills, seam allowances, grain lines, labels
3. SVG Export — triggers browser download as `pattern.svg`

**Export PDF:**
1. App Shell — POSTs `{ elements, pieces, paper_size, single_page }` to `/api/export/pdf`
2. Export Router — calls `tile_pdf()` in PDF Tiler
3. PDF Tiler — lays out elements across A4/Letter pages with crosshair registration marks
4. Export Router — returns binary PDF; browser download triggered

---

### Pattern Persistence (Save to DB) Flow
**Trigger:** API call to `POST /api/patterns` (browser or future "Save to cloud" feature).

1. Patterns Router — receives `PatternCreate` body; validates via Pattern Schemas
2. Patterns Router — extracts denormalised metadata (piece count, waist, hip)
3. Patterns Router — writes `Pattern` ORM row to SQLite via SQLAlchemy
4. Patterns Router — returns `PatternResponse` JSON

---

### Template Learning Flow
**Trigger:** Pattern generation encounters a garment detail not in `_PARAMETRIC_DETAILS`.

1. Pattern Engine — calls `detect_unsupported_details(features)`
2. LLM Fallback — for each unsupported detail: calls `store.find(detail, garment_type)`
3. Learned Pieces (miss) — returns `None`
4. LLM Fallback — calls Anthropic Claude with parametric-formula prompt
5. LLM Fallback — parses JSON response → `PieceTemplate`
6. Learned Pieces — saves template to `learned.json`; future requests hit cache
7. LLM Fallback — calls `apply_template(template, measurements)` → `PieceSpec`
8. Pattern Engine — serialises and appends the novel piece to the `.psnap` output
