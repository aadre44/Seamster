## Overview

**Seamster** is a browser-based sewing-pattern editor with an AI photo-to-pattern pipeline. The **frontend** (React + TypeScript + Vite) is a single-page SVG canvas editor whose entire state lives in one `useReducer` context; users draw lines/curves that snap together, close them into pattern pieces, drive dimensions with measurement formulas, and export SVG/PDF. The **backend** (FastAPI + Python) exposes a thin REST layer over three subsystems: a **vision analyzer** (photo → garment features), a **parametric pattern engine** (features + measurements → `.psnap` geometry), and an **LLM instruction generator**. All AI calls funnel through a provider-agnostic `app/llm/` layer that can target **Anthropic Claude** (cloud) or a **local Ollama** server, switchable at runtime. The `.psnap` JSON document is the contract that ties the two layers together — the backend emits it, the frontend loads it.

## Layers & Modules

### Frontend

#### App Shell · `frontend/src/App.tsx`
**Role:** Top-level layout — header (Pattern | Assembly | 3D Body view tabs, AI Assist / Instructions buttons, ModelToggle), tool/canvas/sidebar rows, status bar; also owns the Save/Open buttons (format in `utils/psnap.ts`) and the PDF-export fetch.
**Inputs:** User clicks; editor state via `useEditor`.
**Outputs:** Rendered app; `LOAD_STATE` dispatches; downloads (`.psnap`, PDF).
**Depends on:** Editor Context, Canvas, Toolbar, Properties Panel, Measurement Panel, AI Assist Modal, Instructions Panel, Assembly View, Model Toggle, SVG Export, `POST /api/export/pdf`.

#### Entry · `frontend/src/main.tsx`
**Role:** React root; mounts `<App>` in StrictMode.
**Depends on:** App Shell.

#### Editor Context · `frontend/src/context/EditorContext.tsx`
**Role:** Single source of truth for the editor — elements, pieces, measurements, connections, selection, tool, zoom/pan, undo/redo (50 levels), instructions, last features/measurements. `useReducer` with ~30 action types.
**Inputs:** Dispatched actions.
**Outputs:** `state` + `dispatch` to every editor component.
**Depends on:** FE Types, Piece Transforms.

#### Canvas · `frontend/src/components/Canvas.tsx`
**Role:** The SVG drawing surface — pan/zoom/grid/rulers, all drawing tools (line, curve, point, seam-allowance, grain, notch, eraser, select), piece closing/filling, drag-move. Largest FE module (~2k lines).
**Inputs:** Pointer/keyboard events; editor state.
**Outputs:** Element/piece dispatches; live snap indicators.
**Depends on:** Editor Context, Snap Engine, Piece Transforms, FE Types.

#### Toolbar · `frontend/src/components/Toolbar.tsx`
**Role:** Left tool rail + bottom toggles (grid/snap/seam-allowance/help).
**Depends on:** Editor Context, Help Panel.

#### Properties Panel · `frontend/src/components/PropertiesPanel.tsx`
**Role:** Context-sensitive editor for the selected element/piece — coordinates, length/formula, fold toggle, piece name/cut-qty/transforms.
**Depends on:** Editor Context, Formula Eval, Units, Piece Transforms, Canvas (`throughPointToCP`).

#### Measurement Panel · `frontend/src/components/MeasurementPanel.tsx`
**Role:** Body-measurement inputs with metric/imperial display and range validation.
**Depends on:** Editor Context, Units.

#### AI Assist Modal · `frontend/src/components/AIAssistModal.tsx`
**Role:** Phase-2 wizard — upload garment photo(s) → review/correct detected features + enter measurements → generate. Has a dev mode to paste saved analysis JSON.
**Inputs:** Garment type, image files, measurement edits.
**Outputs:** `POST /api/analyze`, `POST /api/generate`; `LOAD_STATE` of the returned `.psnap`.
**Depends on:** Editor Context, FE Types, `api/analyze`, `api/generate`.

#### Instructions Panel · `frontend/src/components/InstructionsPanel.tsx`
**Role:** Slide-out drawer that requests and renders step-by-step sewing instructions; Regenerate button.
**Outputs:** `POST /api/instructions`; `SET_INSTRUCTIONS` dispatch.
**Depends on:** Editor Context, FE Types, `api/instructions`.

#### Assembly View · `frontend/src/components/AssemblyView.tsx`
**Role:** Alternate canvas view showing how pieces connect — BFS edge-to-edge "assembly" layout or grid layout with colour-coded seam guide.
**Depends on:** Editor Context, FE Types.

#### Model Toggle · `frontend/src/components/ModelToggle.tsx`
**Role:** Header control to switch the active backend LLM provider (Claude ↔ Local Ollama) at runtime.
**Outputs:** `GET`/`POST /api/provider`.
**Depends on:** `api/provider`.

#### Help Panel · `frontend/src/components/HelpPanel.tsx`
**Role:** Static tool reference overlay.

#### Snap Engine · `frontend/src/snapping/snapEngine.ts`
**Role:** Pure snapping math — endpoint/midpoint/grid/angle snapping within an 8px radius, plus screen↔cm conversion.
**Depends on:** FE Types.

#### SVG Export · `frontend/src/export/svgExport.ts`
**Role:** Client-side SVG document generation from elements/pieces (mirrors Canvas geometry).
**Depends on:** FE Types.

#### Formula Eval · `frontend/src/utils/formulaEval.ts`
**Role:** Sandboxed tokenizer/parser for parametric dimension formulas (no `eval`).

#### Piece Transforms · `frontend/src/utils/pieceTransforms.ts`
**Role:** Centroid, flip H/V, rotate, mirror helpers operating on a piece's elements.
**Depends on:** FE Types.

#### Units · `frontend/src/utils/units.ts`
**Role:** Metric/imperial display conversion and labels.

#### Legacy Wizard *(unused)* · `frontend/src/context/PatternContext.tsx`, `components/{PhotoUpload,FeatureReview,MeasurementForm,PatternPreview,DownloadStep}.tsx`
**Role:** An earlier standalone photo-to-pattern wizard + its own context. These import only each other and are **not** wired into `App.tsx` (the live flow lives in AI Assist Modal). Retained but dead.

### Shared

#### FE Types · `frontend/src/types/index.ts`
**Role:** TypeScript contracts shared across the frontend — `CanvasElement` union, `PatternPiece`, `SeamConnection`, `EditorState`, `GarmentFeatures`, `Measurements`, `SewingInstructions`, garment-type constants. Mirrors the backend Pydantic models and the `.psnap` shape.

#### .psnap Document *(format contract)*
**Role:** The JSON document exchanged between layers: `{ version, elements[], pieces[], measurements, connections?, instructions? }`. Produced by the pattern engine, consumed by `LOAD_STATE`, persisted to file and (optionally) the DB.

### Backend

#### App Entry · `backend/app/main.py`
**Role:** Builds the FastAPI app — loads `.env`, CORS, lifespan that creates DB tables, mounts all routers under `/api`, exposes `/api/health` (reports active provider/model) and `/api/garment-types`.
**Depends on:** all routers, LLM layer, Database.

#### API · Analyze · `backend/app/api/analyze.py`
**Role:** `POST /api/analyze` — validates JPEG/PNG ≤10 MB, calls the vision analyzer.
**Outputs:** `GarmentFeatures`.
**Depends on:** Vision Analyzer, Models.

#### API · Generate · `backend/app/api/generate.py`
**Role:** `POST /api/generate` — features + measurements → `.psnap` JSON.
**Depends on:** Pattern Engine, Models.

#### API · Instructions · `backend/app/api/instructions.py`
**Role:** `POST /api/instructions` — features + measurements + pieces → sewing instruction JSON.
**Depends on:** Instruction Generator, Models.

#### API · Provider · `backend/app/api/provider.py`
**Role:** `GET`/`POST /api/provider` — read or switch the active LLM provider at runtime.
**Depends on:** LLM Factory.

#### API · Templates · `backend/app/api/templates.py`
**Role:** `GET`/`DELETE /api/templates[/{id}]` — inspect/clean the learned-piece store.
**Depends on:** Learned Pieces.

#### API · Patterns · `backend/app/api/patterns.py`
**Role:** CRUD `/api/patterns` — persist `.psnap` documents to the database with denormalized metadata. (Available API; the live frontend currently saves to file, not this endpoint.)
**Depends on:** Database, DB Models, Schemas.

#### API · Export · `backend/app/api/export.py`
**Role:** `POST /api/export/pdf` — tiled or single-page PDF.
**Depends on:** PDF Tiler.

#### Vision Analyzer · `backend/app/vision/analyzer.py`
**Role:** Builds the vision prompt, calls the LLM layer with the image(s), parses/validates JSON into `GarmentFeatures`, and infers pocket details from free-text notes.
**Depends on:** Vision Prompts, LLM Layer, Models.

#### Vision Prompts · `backend/app/vision/prompts.py`
**Role:** Per-garment-type system/user prompt templates for vision analysis.

#### Pattern Engine · `backend/app/patterns/engine.py`
**Role:** Orchestrator — routes by garment type to the right block builder, serialises pieces to `.psnap` elements, computes seam connections, then appends LLM-fallback novel pieces.
**Inputs:** `GarmentFeatures`, `Measurements`.
**Outputs:** `.psnap` dict.
**Depends on:** Pattern Blocks, Geometry, Modifiers, LLM Fallback, Models.

#### Pattern Blocks · `backend/app/patterns/{skirts,shirts,trousers,dresses,jackets}.py`
**Role:** Parametric block drafters — each turns measurements + style flags into `PieceSpec` outlines (with darts, grain lines, optional detail pieces) for its garment family.
**Depends on:** Geometry.

#### Modifiers · `backend/app/patterns/modifiers.py`
**Role:** Legacy silhouette/feature modifiers (still used for skirts).
**Depends on:** Geometry.

#### Geometry · `backend/app/patterns/geometry.py`
**Role:** 2D primitives — `Point`, `CurveSegment`, polygon offset, bezier math.

#### Instruction Generator · `backend/app/patterns/instruction_generator.py`
**Role:** Builds the sewing-instructor prompt, computes a garment-weighted `max_tokens`, calls the LLM layer, raises on truncation, parses the JSON.
**Depends on:** LLM Layer, Models.

#### LLM Fallback · `backend/app/patterns/llm_fallback.py`
**Role:** For garment details the parametric engine can't draft, returns a learned template if one exists, else asks the LLM for a parametric piece description and saves it as a reusable template.
**Depends on:** Learned Pieces, LLM Layer, Models.

#### Learned Pieces · `backend/app/patterns/learned_pieces.py`
**Role:** JSON-backed store of `PieceTemplate`s plus a sandboxed formula evaluator that turns templates into concrete `PieceSpec`s for any body size.
**Outputs:** Reads/writes `patterns/templates/learned.json`.
**Depends on:** Geometry, Models.

#### LLM Layer · `backend/app/llm/{base,factory,anthropic_provider,ollama_provider}.py`
**Role:** Provider-agnostic completion interface. `factory.get_provider()` selects Anthropic or Ollama (env default + runtime override), and the shared retry/JSON helpers wrap both. `base.py` defines the `LLMProvider` ABC, `LLMResponse`, and a common error hierarchy.
**Inputs:** system/user text, optional images, `max_tokens`.
**Outputs:** `LLMResponse(text, truncated)`.
**Depends on:** Anthropic SDK, Ollama server (via providers).

#### Models · `backend/app/models/{features,measurements}.py`
**Role:** Pydantic request/response shapes — `GarmentType`, `GarmentFeatures`, `Measurements` (with validation bounds).

#### Schemas · `backend/app/schemas/pattern.py`
**Role:** Pydantic schemas for `.psnap` geometry and the patterns-CRUD request/response bodies.

#### PDF Tiler · `backend/app/export/pdf_tiler.py`
**Role:** Renders elements/pieces (+ optional instructions) into a tiled or single-page PDF via reportlab.

#### Database · `backend/app/database.py`
**Role:** SQLAlchemy engine/session setup (`DATABASE_URL`, default SQLite) and the `get_db` dependency.
**Outputs:** Sessions bound to the SQLite/Postgres DB.

#### DB Models · `backend/app/db_models.py`
**Role:** `Pattern` ORM table — id, name, garment type, denormalized metadata, timestamps, full `.psnap` JSON blob.
**Depends on:** Database.

### Infra

#### Learned Templates · `backend/app/patterns/templates/learned.json`

## Data Flows

### Photo → Pattern (AI Assist)
**Trigger:** User clicks "AI Assist", uploads a garment photo, and clicks Generate.

1. AI Assist Modal — `POST /api/analyze` with image(s) + garment type
2. API · Analyze — validates and calls the vision analyzer
3. Vision Analyzer — builds prompt, calls LLM layer with images
4. LLM Factory → active provider → external LLM — returns JSON
5. Vision Analyzer — parses/validates → `GarmentFeatures` back to the modal
6. AI Assist Modal — user reviews features + enters measurements → `POST /api/generate`
7. Pattern Engine — routes by garment type → block builder drafts pieces
8. LLM Fallback — fills any unsupported details (template or LLM) → appended
9. Pattern Engine — serialises to `.psnap`, computes seam connections
10. AI Assist Modal — `LOAD_STATE` into Editor Context → Canvas renders the pattern

### Generate Sewing Instructions
**Trigger:** User opens the Instructions drawer (or clicks Regenerate).

1. Instructions Panel — `POST /api/instructions` with features + measurements + pieces
2. Instruction Generator — builds prompt, computes max_tokens, calls LLM layer
3. LLM Factory → active provider → external LLM — returns instruction JSON
4. Instruction Generator — parses → sections
5. Instructions Panel — `SET_INSTRUCTIONS` into Editor Context → rendered

### Switch LLM Provider
**Trigger:** User clicks Claude / Local in the header Model Toggle.

1. Model Toggle — `POST /api/provider {provider}`
2. API · Provider — `set_provider()` sets a process-memory override
3. LLM Factory — next `get_provider()` returns the new provider for all AI calls

### Manual Draw → Piece
**Trigger:** User draws with a tool on the canvas.

1. Canvas — pointer events, Snap Engine resolves snap point
2. Canvas — `ADD_ELEMENT` / close outline → `ADD_PIECE` into Editor Context
3. Properties Panel — edits coordinates/formula (Formula Eval) → `UPDATE_ELEMENT`

### Export PDF
**Trigger:** User clicks Export PDF.

1. App Shell — `POST /api/export/pdf` with elements/pieces/options
2. API · Export → PDF Tiler — reportlab renders tiled/single PDF
3. App Shell — downloads the returned PDF bytes

### Novel-Piece Learning *(sub-flow of Generate)*
**Trigger:** Pattern engine encounters a detail it can't draft parametrically.

1. LLM Fallback — `detect_unsupported_details`
2. Learned Pieces — `store.find` template; on hit → `apply_template`
3. On miss — LLM layer returns a parametric piece description → saved to `learned.json` → applied

### Persist Pattern to DB *(API available)*
**Trigger:** A client calls the patterns CRUD API.

1. API · Patterns — validate `.psnap` geometry, extract metadata
2. Database / DB Models — insert/update `Pattern` row → SQLite
